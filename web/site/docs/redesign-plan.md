# Редизайн сайта «Тропа» по эталону «Научные тропы»

Эталон: `nauchnye-tropy-v4.html` (прототип, 2144 строки, один файл).
Цель: перенести его визуальный язык и расширить сайт новыми разделами, **сохранив
все наши рабочие функции**.

---

## 1. Ключевое решение: что во что переносим

Эталон и наш сайт устроены противоположно, и это определяет весь план.

| | Эталон | Наш сайт |
|---|---|---|
| Архитектура | SPA, hash-роутинг, всё в одном HTML | статика: `build.py` + Jinja → 51 страница |
| Данные | JS-массивы в файле | единая база знаний (Obsidian) → генератор |
| Бэкенд | нет | FastAPI: чат, гео, методичка, PDF |
| Конструктор маршрута | имитация (псевдослучайный подбор, спиннер 520 мс) | нет |
| Научный гид | демо-режим по локальному банку | рабочий, GigaChat + контекст страницы |
| Карта маршрута | Яндекс.Карты, ключ пустой → не грузится | Leaflet + гео-режим (позиция, пеший маршрут) |
| Формы | `preventDefault()`, «отправка не настроена» | — |
| PDF | `window.print()` | Typst-методичка с иллюстрациями |
| SEO | client-side рендер, один URL | у каждого сюжета свой URL, мета, sitemap |

**Решение: переносим дизайн эталона в нашу архитектуру, а не наоборот.**

Обоснование: эталон — это прототип внешнего вида. Всё, что в нём выглядит рабочим,
на деле заглушка. У нас наоборот — функции живые, а «кожа» устарела. Переезд на SPA
стоил бы нам SEO (40+ сюжетов сейчас индексируются каждый по своему адресу),
генерации из базы знаний, методички с PDF и гео-режима карты. Поэтому берём из
эталона **визуальный язык, структуру лендинга и недостающие компоненты**, а
реализуем их в Jinja-шаблонах поверх наших API.

## 2. Дизайн-система (переносится как есть)

**Палитра.** Поверхности: `--paper:#FBF8F1`, `--milk:#F6F1E6`, `--sand:#EFE7D3`,
`--mist:#EAF1F5`, `--meadow:#EAF2E1`, `--card:#FFF`. Текст: `--ink:#22333C`,
`--ink-soft:#5B6C75`, `--line:#DCD4C4`. Акценты парами base/600: sky `#2E9BD6`/`#1B7CB4`,
grass `#4EA75D`/`#337E45`, terra `#E9863B`/`#C05F14`, violet `#7A6FE0`/`#5A4EC9`,
teal `#23A79A`/`#0E7F74`, sun `#F6BB2E`, coral `#F26B57`/`#D94F37`.
`--accent` переключается по контексту (в конструкторе — по выбранной аудитории).

**Типографика.** Заголовки — Unbounded (500/600), текст — Golos Text (400/500/600),
метки и цифры — JetBrains Mono. Всё на `clamp()`: h1 `clamp(32px,4.6vw,56px)/1.09`,
h2 `clamp(24px,3.2vw,38px)/1.14`, h3 `clamp(19px,2.2vw,25px)/1.2`, body `17px/1.65`.

**Тени:** `--sh-sm:0 2px 10px rgba(34,51,60,.06)`, `--sh-md:0 12px 32px rgba(34,51,60,.10)`,
`--sh-lg:0 24px 60px rgba(34,51,60,.14)`. **Easing** один на всё:
`cubic-bezier(.22,1,.36,1)`. Радиусы: пилюли `999px`, карточки 14–28px по размеру блока.

**Отличие от эталона — шрифты подключаем локально, не с Google Fonts.** Эталон тянет
их с `fonts.googleapis.com`; для аудитории в РФ это лишняя внешняя зависимость с
непредсказуемой скоростью, а для сайта, который открывают в поле с телефона, — риск
получить страницу без заголовочного шрифта. Кладём woff2 в `site/assets/fonts/`
с `font-display:swap`.

## 3. Карта работ по страницам

### Берём из эталона и наполняем нашими данными
- **Главная** — полностью новая структура: hero с SVG-иллюстрацией, «три входа»
  (Территориям / Гидам / Учителям), проблема→решение, 4 шага прохождения тропы,
  конструктор, маршруты, тизер библиотеки, гид, этапы работы, команда, форма заявки.
- **Библиотека сюжетов** — наша `/storylines/` получает фильтры (дисциплина,
  окружение, поиск с debounce) и карточки эталона. Фильтрация на клиенте по уже
  отрендеренным карточкам — статика и SEO сохраняются.
- **Страница сюжета** — оформление эталона поверх наших уровней-табов; боковая
  панель «где встречается / на каких маршрутах / школьная привязка».
- **Страница маршрута** — верстка эталона, но карта **наша** (Leaflet + гео-режим),
  не Яндекс.

### Делаем впервые
- **Конструктор маршрута.** В эталоне это имитация. У нас есть сюжеты с предметами,
  классами и окружением — можно собрать **честный** подбор: генератор выкладывает
  индекс сюжетов в JSON, клиент фильтрует по параметрам и считает время (7 мин на
  точку + 5 мин переход). Никакого псевдослучайного «как бы подбора».
- **Три входа под аудитории** — отдельные страницы: территориям, гидам, учителям.
- **Форма заявки** — с реальной отправкой через наш FastAPI (в эталоне заглушка).

### Не берём
- SPA-роутинг и client-side рендер списков — ломает SEO.
- Яндекс.Карты — у нас Leaflet с рабочим гео.
- «Скачать PDF» через `window.print()` — у нас настоящая методичка на Typst.

## 4. Декомпозиция

**Этап 0. Фундамент** — блокирует всё остальное.
1. Скачать и положить шрифты локально (Unbounded, Golos Text, JetBrains Mono), `@font-face`.
2. Вынести дизайн-токены эталона в `site/assets/tokens.css`, подключить в `base.html`.
3. Базовые компоненты: кнопки (пилюли, primary/ghost), карточки, чипы, поля ввода,
   `.eyebrow`, `.lead`, `.mono`.
4. Scroll-reveal: `.rev`/`.d1`/`.d2`/`.d3` + IntersectionObserver (`threshold .12`),
   плюс `prefers-reduced-motion` — отключение анимаций.

**Этап 1. Каркас.** Шапка sticky с `backdrop-filter` и тенью при скролле; расширенное
меню (Идея, Как работает, Для кого, Маршруты, Библиотека, Гид, Учителю) + CTA;
бургер-меню на ≤980px; футер.

**Этап 2. Главная.** Секции по списку выше. Hero-иллюстрация — inline SVG с медленными
анимациями (облака, солнце, бегущий пунктир тропы, птицы). Цифры в hero берём из
реальных данных генератора (число сюжетов, дисциплин), не хардкодим.

**Этап 3. Библиотека.** Фильтры + поиск (нормализация ё→е, дефисы, lowercase),
счётчик результатов, пустое состояние.

**Этап 4. Сюжет.** Табы уровней с клавиатурной навигацией (←/→, roving tabindex,
`aria-selected`), боковая панель, схемы.

**Этап 5. Маршрут.** Факты маршрута, список точек, наша карта с гео-кнопками.

**Этап 6. Конструктор.** Индекс сюжетов в JSON при сборке; кастомный Dropdown с
полной клавиатурой и aria-listbox; расчёт длительности; результат с анимацией
появления; пересборка; для трека «Учителям» — переход в нашу методичку.

**Этап 7. Страницы аудиторий + форма заявки** (эндпоинт, валидация, антиспам,
согласие на обработку данных со ссылкой на политику).

**Этап 8. Виджет-бот** — привести к новому визуалу, функциональность не трогать.

**Этап 9. Приёмка.** Адаптив на 375/768/1024/1440; Lighthouse; контраст AA;
клавиатурная навигация; проверка, что **не сломались**: методичка и PDF, гео-режим
карты, виджет-бот, генерация из базы, sitemap и мета-теги.

---

## 5. Чего нельзя сломать

Это главный риск редизайна — потерять работающее ради внешнего вида.

- Контракты API (`/api/chat`, `/api/geo`, `/api/lesson`, `/api/lesson/pdf`) и
  `data-bot-api` на `<body>`.
- Единый источник контента: правки только в базе знаний, сайт генерируется
  (см. `90-meta/Гард единого источника`).
- Отдельный URL и мета-теги у каждого сюжета.
- Взаимная фильтрация «класс ↔ предмет» в форме учителя.
- Версионирование ассетов `?v=<хеш>` — иначе правки не доедут до кэшей.

> `templates/`, бэкенд FastAPI в `site-bar/server/`. Эталон — прототип: его конструктор,
> гид, формы и карта нерабочие, не копируй их логику, копируй оформление и структуру.

> `Skill(cool-design)` — это обязательный протокол дизайн-работы в проекте.
>
> **Дизайн-система:** токены, типографика и тени — из раздела 2 этого документа,
> значения брать точно. Шрифты подключить локально из `site/assets/fonts/`, не с Google
> Fonts. Один общий `tokens.css`, а не инлайн-стили на каждой странице.
>
> **Порядок:** этапы 0→9 из раздела 4, по одному, с деплоем и проверкой между ними.
> Не начинай следующий этап, пока предыдущий не проверен на боевом.
>
> **Каждую правку проверяй тремя способами** (правило проекта `triple-verification`):
> программно (DOM/curl), визуально (скриншот), симуляцией действия пользователя.
> Отдельно после каждого этапа прогоняй чек-лист раздела 5 — что не должно сломаться.
>
> **Данные берём из генератора,** а не хардкодим: число сюжетов и дисциплин в hero,
> карточки маршрутов, индекс для конструктора. Если в эталоне цифра зашита в HTML —
> у нас она должна считаться при сборке.
>
> **Конструктор маршрута делаем честным:** подбор из реального индекса сюжетов по
> предмету/классу/окружению/времени, а не псевдослучайный. Если параметрам ничего не
> соответствует — так и сказать, а не выдать случайное.
>
> После каждого этапа: коммит в репозиторий, зеркало, запись в `90-meta/LOG.md`.
